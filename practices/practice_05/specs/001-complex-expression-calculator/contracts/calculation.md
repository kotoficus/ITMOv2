# Контракт вычисления v1

Статус: конкретизация Spec для просмотра до реализации. Применяется к
новому интерфейсу выражений; не меняет сигнатуры старого `calculator.js`.

## Вызов

`calculate(expression)` — синхронная функция нового модуля `src/expression.js`.
Принимает исходную строку без предварительного обрезания пробелов:
позиции ошибок относятся именно к переданной строке.
Ожидаемые ошибки ввода и арифметики возвращаются данными, без исключения
для вызывающего UI. Функция не читает и не изменяет файлы или историю.

## Успех

Для `(1+2i)*(3-4i)`:

```json
{
  "ok": true,
  "value": { "re": 11, "im": 2 },
  "text": "11 + 2i"
}
```

- `ok` — дискриминатор результата.
- `value.re` и `value.im` — конечные числа, никогда не `NaN`/бесконечность.
- Обе компоненты всегда присутствуют. Для `2+3`: `{ "re": 5, "im": 0 }`.
- Отрицательный ноль нормализуется в `0` в обеих компонентах.
- `text` — отображение значения по правилам ниже. Поле `error` отсутствует.
- Результат JSON-совместим, не содержит классов, функций или исключений.

## Отказ

Для `2+`:

```json
{
  "ok": false,
  "error": {
    "code": "SYNTAX_ERROR",
    "message": "Некорректное выражение.",
    "span": { "start": 2, "end": 2 }
  }
}
```

Поля `value` и `text` отсутствуют. `error.span` всегда присутствует:
объект диапазона либо `null`, когда строковой позиции нет.
UI принимает решения по `code`, а `message` показывает человеку.

| Код | Сообщение | Когда | Позиция |
|---|---|---|---|
| `INVALID_INPUT` | `Выражение должно быть строкой.` | Аргумент не примитивная строка | `null` |
| `EMPTY_EXPRESSION` | `Введите выражение.` | Строка пуста или содержит только разрешённые пробелы | Вся исходная строка |
| `SYNTAX_ERROR` | `Некорректное выражение.` | Недопустимый символ, порядок токенов, скобки, лишний ввод | Ошибочный токен/символ либо конец строки |
| `DIVISION_BY_ZERO` | `Деление на ноль.` | У вычисленного делителя обе компоненты равны нулю | Полное подвыражение делителя |
| `NUMERIC_OVERFLOW` | `Число выходит за допустимый диапазон.` | Литерал, промежуточное вычисление или результат выходит за конечный числовой диапазон | Литерал либо подвыражение, где обнаружено переполнение |

Проверки идут в порядке: тип → пустота → лексический анализ всей строки →
синтаксический разбор до конца → вычисление. Поэтому `1/0+` возвращает
`SYNTAX_ERROR`. Вычисление бинарных узлов идёт слева направо: сначала
левый операнд, затем правый, затем операция; возвращается первая
обнаруженная ошибка. `1/0+2/0` указывает на первый нулевой делитель.

Непредвиденные ошибки программирования не маскируются под один из пяти
кодов пользовательского ввода: реализация ловит только внутренние
ошибки калькулятора, а не любое исключение.

## Позиции

- Нумерация с нуля, единицы — UTF-16, как индексы строк JavaScript.
- `start` включительно, `end` исключительно; диапазон удовлетворяет
  `0 <= start <= end <= expression.length`.
- Отсутствующий операнд или закрывающая скобка: диапазон
  `{start: expression.length, end: expression.length}`.
- Для `2 3` ошибка у `3`: `{start: 2, end: 3}`.
- Для `2^3` ошибка у `^`: `{start: 1, end: 2}`.
- Для `1/(i-i)` ошибка у делителя `(i-i)`: `{start: 2, end: 7}`.
- Для `1/(2-2)` диапазон аналогичен и включает обе скобки делителя.
- Для строки из трёх пробелов: `{start: 0, end: 3}`;
  для пустой — `{start: 0, end: 0}`.

## Отображение

| Значение `(re, im)` | `text` |
|---|---|
| `(0, 0)` | `0` |
| `(5, 0)` | `5` |
| `(0, 1)` | `i` |
| `(0, -1)` | `-i` |
| `(0, 2)` | `2i` |
| `(0, -2)` | `-2i` |
| `(3, 1)` | `3 + i` |
| `(3, -2)` | `3 - 2i` |
| `(-0.2, 0.4)` | `-0.2 + 0.4i` |

Для ненулевых компонент используется стандартное строковое представление
конечного числа JavaScript без дополнительного округления и без локальной
десятичной запятой. Между действительной частью, знаком и мнимой частью
смешанного числа — по одному пробелу. Коэффициент `1` у `i` опускается.
Близкие к нулю значения не обнуляются с помощью epsilon.

На очень больших/малых значениях `text` может содержать экспоненциальную
запись стандартного форматирования. Это строка отображения, а не обещание
повторного разбора как выражения; для истории сохраняется исходный ввод.

## Точность и совместимость

Вычисления выполняются с обычной точностью JavaScript Number (binary64).
Для приёмочных сравнений дробных компонент:
`abs(actual - expected) <= 1e-12 * max(1, abs(expected))`.
Эта погрешность относится к тестам, а не к определению нулевого делителя.
Переполнение литералов и арифметики — управляемый отказ; конечная точность
и округление слишком малых чисел не заменяются произвольной точностью.

Существующие `add`, `subtract`, `multiply`, `divide` из `src/calculator.js`
остаются прежним интерфейсом для вещественных чисел. Их 7 тестов сохраняются.
Объект результата выражения возвращает только новый `calculate`.
