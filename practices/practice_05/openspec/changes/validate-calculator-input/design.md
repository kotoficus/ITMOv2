# Design

Статус: исторический черновик, заменённый Spec Kit-пакетом
`specs/001-complex-expression-calculator`. Не является активным планом.

## Context

См. `proposal.md`, раздел Why. Исходный `src/calculator.js` экспортирует
`add`, `subtract`, `multiply`, `divide`. Семь тестов используют `node:test`.
Baseline: `evidence/baseline.txt`, 7/7. Документ нужен, чтобы до кода
зафиксировать технические решения о приведении типов и приоритете ошибок.

## Goals / Non-Goals

**Goals:** общая проверка без изменения экспортов и существующего runner.

**Non-Goals:** конвертация строк UI в числа, зависимости, отдельный backend,
проверка результата на переполнение, изменение точности JavaScript.

## Decisions

1. Внутренняя функция проверяет оба аргумента через `Number.isFinite`.
   Альтернатива `isFinite` приводит типы и принимает, например, `null`.
   Отдельная проверка `typeof` избыточна для `Number.isFinite`.
2. Все четыре экспорта вызывают общую проверку до вычисления.
   В `divide` проверка аргументов идёт перед существующей проверкой нуля.
   Это задаёт единый тип ошибки даже при одновременно неверном первом
   аргументе и нулевом втором. Альтернатива — различный приоритет ошибок.
3. Исходные 7 тестов сохраняются. Дополнительные тесты проверяют неверные
   значения на обеих позициях для каждого экспорта, допустимые ноль,
   отрицательные и дробные аргументы, а также приоритет ошибки в `divide`.

## Risks / Trade-offs

- Вызовы со строками перестанут работать → явно отмечено в proposal как
  изменение контракта; будущий UI должен разбирать строки отдельно.
- Конечные аргументы могут дать бесконечный результат → сохраняем прежнюю
  арифметику; проверка переполнения не входит в эту фичу.

## Migration Plan

Изменение локального учебного модуля после согласования спецификации.
Проверка: `npm test` в `practices/practice_05`.
Для возврата к исходному поведению существует источник `practice-04:practices/practice_04/src/calculator.js`.
