# Chain of Verification

**Артефакт Практики 1: `adr.md`**

## 1. Техника и зачем она здесь

CoVe проверяет утверждения ADR вопросами к источникам, чтобы убрать ложный статус `accepted` и любые факты без опоры.

## 2. Вход (фрагмент выбранного артефакта)

Черновик утверждал (или допускал) статус «accepted» и недостаточно явно отделял источники от домыслов в «Контексте».

## 3. Запрос на проверку

```text
По adr.md задай 3–5 проверочных вопросов. На каждый — источник
(TRAINING_PR.diff / README / нет данных). Исправь только adr.md.
```

## 4. Первоначальный ответ (до правки)

«Статус accepted; human-in-the-loop; API и помощник связаны в одном решении.»

## 5. Вопросы и результаты проверки

| # | Вопрос | Источник | Результат |
|---|---|---|---|
| 1 | Зафиксировано ли внешнее принятие ADR (`accepted`)? | README / diff | **Нет** → статус `proposed` |
| 2 | Есть ли в diff `POST /api/reviews` и `payload["diff"]`? | `TRAINING_PR.diff` | **Да** |
| 3 | Есть ли `ReviewService.review` и `llm.generate`? | `TRAINING_PR.diff` | **Да** |
| 4 | Задаёт ли README формат помощника и запрет approve/merge? | README Практики 1 | **Да** |
| 5 | Подтверждён ли единый runtime чат+API? | — | **Нет данных** → не утверждать |

## 6. Исправленный результат

Статус `proposed`; в «Контексте» — таблица утверждение→источник; запрет писать единый runtime как факт.

## 7. Что приняли / отклонили

- **Приняли:** таблицу источников в «Контексте»; статус `proposed`.
- **Отклонили:** `accepted` как факт курса без записи.

## 8. Изменение в выбранном артефакте

- Файл: `practices/practice_01/adr.md`
- Раздел: шапка (статус), «Контекст» (таблица источников)
- Что стало: проверяемые утверждения + «Открытый вопрос» для HTTP-кода.

## 9. Проверка

Каждая строка таблицы в «Контексте» либо указывает файл, либо «Открытый вопрос» / «не утверждать».
