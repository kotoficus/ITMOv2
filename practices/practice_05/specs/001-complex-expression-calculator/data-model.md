# Data model: первая часть калькулятора

## ComplexValue

| Поле | Тип | Инвариант |
|---|---|---|
| `re` | `number` | Конечное значение, `-0` нормализован в `0` |
| `im` | `number` | Конечное значение, `-0` нормализован в `0` |

Вещественное `a` представляется `{re: a, im: 0}`. Операции возвращают новые
объекты, не мутируют операнды. Нулевое значение имеет обе компоненты `0`;
epsilon для этого сравнения не используется.

Для `z = a + bi`, `w = c + di`:

- `z + w = (a+c) + (b+d)i`;
- `z - w = (a-c) + (b-d)i`;
- `z * w = (ac-bd) + (ad+bc)i`;
- `z / w = ((ac+bd)/(c²+d²)) + ((bc-ad)/(c²+d²))i`, если `w != 0`.

Последняя формула задаёт математический смысл; в реализации знаменатель
масштабируется для уменьшения переполнения квадратов (см. research).
Переполнение вычисления не создаёт допустимый `ComplexValue`.

## SourceSpan

`{start, end}` — полуоткрытый диапазон UTF-16 в исходной строке.
Все токены и узлы дерева имеют span. EOF имеет нулевую длину в конце ввода.

## Token

`{type, lexeme, span}`. Типы: `NUMBER`, `I`, `PLUS`, `MINUS`, `STAR`,
`SLASH`, `LPAREN`, `RPAREN`, `EOF`. `lexeme` сохраняет точный текст токена.
Лексер не выполняет числовое преобразование или арифметику.

## ExpressionNode (AST)

| `type` | Дополнительные поля | Смысл |
|---|---|---|
| `Literal` | `kind: real/imaginary`, `coefficient: string` | Для `i` коэффициент `"1"`; для `2i` — `"2"` |
| `Unary` | `operator: +/-`, `operand` | Унарный знак |
| `Binary` | `operator` (`+`, `-`, `*`, `/`), `left`, `right` | Бинарная операция |
| `Group` | `expression` | Скобки, включая их границы в span |

У каждого узла есть `span`. `Literal` хранит исходную десятичную запись,
а не заранее вычисленное число. Преобразование и контроль конечности
выполняет evaluator. `Group` сохраняет диапазон скобок, необходимый,
например, для подсветки делителя `(i-i)`.

Дерево содержит только структуру ввода. Evaluator рекурсивно возвращает
`ComplexValue`, начиная с листьев. Он не читает строку повторно и не
меняет дерево. Синтаксически неверный ввод до evaluator не доходит.

## CalculationResult и CalculationError

Объединение по `ok`: либо `{ok: true, value, text}`, либо
`{ok: false, error: {code, message, span}}`. Полный контракт и примеры —
в [calculation.md](contracts/calculation.md).

Внутренний `CalculationError` переносит те же данные между слоями через
исключение; публичная фасадная функция превращает его в объект отказа.
Ошибку без позиции допустимо использовать только там, где нет исходной
строки (например, неверный тип входа).

## Состояние и следующий этап

В первой части изменяемого состояния нет: каждый вызов независим.
Модель будущей записи истории и переходы append/Undo описаны только в
[history.md](contracts/history.md). В AST и ComplexValue нет истории,
файловых дескрипторов или UI-состояния.
