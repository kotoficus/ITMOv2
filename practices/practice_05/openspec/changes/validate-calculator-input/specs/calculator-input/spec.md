# Calculator input

Статус: заменённый черновик проверки аргументов. Активный Spec:
`specs/001-complex-expression-calculator/spec.md` от корня практики.

## Purpose

Задаёт однозначный контракт числовых аргументов калькулятора и сохраняет
результаты существующих арифметических операций для допустимого ввода.

## ADDED Requirements

### Requirement: Finite numeric arguments

Каждая арифметическая операция MUST принимать два примитивных конечных
числа JavaScript, включая ноль, отрицательные и дробные числа.

#### Scenario: Допустимые аргументы
- **WHEN** переданы `-3` и `0.5`
- **THEN** операция выполняется без ошибки проверки аргументов

### Requirement: Invalid input rejection

Если хотя бы один аргумент не является примитивным конечным числом,
операция MUST выбросить `TypeError` с сообщением
`Arguments must be finite numbers` до вычисления и проверки деления на ноль.

#### Scenario: Невалидный аргумент на любой позиции
- **WHEN** первый или второй аргумент — строка, `null`, `undefined`,
  логическое значение, объект, массив, `BigInt`, `Symbol`, `NaN` или бесконечность
- **THEN** выбрасывается указанный `TypeError`, без приведения типов

#### Scenario: Приоритет проверки аргументов
- **WHEN** выполняется деление `"10"` на `0`
- **THEN** выбрасывается `TypeError("Arguments must be finite numbers")`

### Requirement: Arithmetic compatibility

Для двух допустимых аргументов четыре операции MUST сохранять прежнюю
арифметику JavaScript и тип результата `number`. Переполнение и округление
результата не меняются этим требованием.

#### Scenario: Прежние результаты
- **WHEN** выполняются `2 + 3`, `5 - 3`, `-3 * 4` и `5 / 2`
- **THEN** возвращаются соответственно `5`, `2`, `-12` и `2.5`

### Requirement: Division by zero compatibility

При допустимых аргументах и делителе `0` или `-0` деление MUST сохранять
`Error` с сообщением `Division by zero`.

#### Scenario: Нулевой делитель
- **WHEN** выполняется деление `10` на `0` или `-0`
- **THEN** выбрасывается `Error("Division by zero")`
