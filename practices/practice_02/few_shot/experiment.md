# Few-shot

**Артефакт Практики 1: `adr.md`**

## 1. Техника и зачем она здесь

Few-shot задаёт **формат и детализацию** формулировок в ADR (особенно риск и проверка), чтобы вместо общих фраз появлялись: контур, файл, цитата/источник, проверка, «Открытый вопрос» при отсутствии данных.

## 2. Вход (фрагмент выбранного артефакта)

Было слабо (типичная общая формулировка до доработки):

```text
Главный риск: LLM или API падают без контролируемого ответа.
Как проверим риск: тесты на отсутствующий diff.
```

## 3. Запрос

```text
Ниже примеры хороших и плохих формулировок риска внутри ADR.
Перепиши раздел «Последствия и главный риск» в adr.md по хорошим образцам.
Артефакт только adr.md. Не выдумывай HTTP-код. Не меняй код продукта.
```

### Примеры «хорошо» (2–3)

1. Контур + файл + суть + источник + проверка с фиксацией факта (см. хороший блок в `adr.md`).
2. То же для `llm.generate` без try/except.
3. Явная пометка «желаемый 4xx — Открытый вопрос».

### Примеры «плохо» (1–2)

1. «Нужно сделать API надёжнее и добавить валидацию.»
2. «Обязательно вернуть 422.» (выдуманный контракт)

**Что задают примеры:** формат (контур/файл/проверка), тон (факты, не лозунги), детализация (источник или «Открытый вопрос»).

## 4. Фактический результат

В `adr.md` добавлен подраздел «Примеры формулировки риска (few-shot)» с двумя хорошими и одним плохим образцом; формулировка главного риска приведена к тому же стандарту.

## 5. Что приняли / отклонили

- **Приняли:** шаблон «контур + файл + источник + проверка».
- **Отклонили:** «обязателен 422» как факт; общие пожелания без файла.

## 7. Проверка

Хорошие примеры содержат отсылки к строкам/`payload["diff"]` и `llm.generate` из `TRAINING_PR.diff`; плохой — не содержит файла/цитаты.
