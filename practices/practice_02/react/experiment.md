# ReAct

**Артефакт Практики 1: `adr.md`**

## 1. Техника и зачем она здесь

ReAct сверяет текст ADR с файлами **действиями и наблюдениями**, чтобы цитаты риска и схема совпали с diff/README. Правки — только в `adr.md`.

## 2. Вход

Цель: проверить, что формулировки риска и узлы схемы в `adr.md` соответствуют `TRAINING_PR.diff` и README.

## 3. Ограничения

- Разрешено: читать файлы Практики 1, читать diff, предлагать правки в **`adr.md`**.
- Запрещено: approve, merge, менять код продукта.
- Лимит: **6** шагов.
- Стоп: правка внесена / открытый вопрос без данных / лимит исчерпан.

## 4. Запрос

```text
ReAct, лимит 6. Работай только с adr.md как целевым артефактом.
Сверь риск и схему с TRAINING_PR.diff и README. Внеси правку только в adr.md.
```

## 5. Фактическая цепочка

| Шаг | Мысль → действие | Наблюдение | Дальше |
|---|---|---|---|
| 1 | Проверить API в diff → читать `TRAINING_PR.diff` | Есть `POST /api/reviews`, `payload["diff"]` | Продолжить |
| 2 | Проверить сервис → тот же diff | Есть `review`, `llm.generate`, `{"comment": answer}` | Продолжить |
| 3 | Проверить границы помощника → читать README Практики 1 | Описание + ≤3 риска + проверки; без approve/merge | Продолжить |
| 4 | Сверить текст риска в adr.md с шагами 1–2 | Формулировки совпадают; T2 уже выбран | Продолжить |
| 5 | Сверить схему: узлы API/Svc/LLM | Соответствуют diff; контур A — README | Продолжить |
| 6 | Уточнить подпись связи A→B на схеме (анализ кода B по diff, не «единый runtime») → правка `adr.md` | Схема обновлена | **Стоп** |

## 6. Итог

Подтверждены элементы контура B из diff и границы контура A из README. В схеме уточнена пунктирная связь: помощник **анализирует** код B по diff, а не является тем же процессом.

## 7. Что приняли / отклонили

- **Приняли:** уточнение подписи на схеме в `adr.md`.
- **Отклонили:** правки `analysis.md` / тестов — другой артефакт; патч `app/api.py`.
