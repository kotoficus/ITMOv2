# Контракт следующего этапа: история JSON и Undo

Статус: граница интеграции, зафиксированная при подготовке первой части.
Хранилище, загрузка, запись и Undo **не реализуются в текущей части**.
Текущий `calculate` остаётся чистым и ничего сюда не записывает.

## Запись и порядок

Историю в будущем изменяет отдельный слой действий пользователя:

1. Он передаёт исходную строку в `calculate`.
2. При `ok: true` добавляет одну запись `{expression, value}` в конец
   истории и сохраняет JSON. Исходная строка сохраняется без trim.
3. При `ok: false` история и файл остаются прежними. Ошибка не становится
   записью и не меняет цель следующего Undo.
4. Повторный успешный расчёт того же выражения создаёт отдельную запись:
   история отражает действия, а не уникальные выражения.

Записи идут от старых к новым. Идентификаторы, время, результат `text`,
дерево выражения и сообщения об ошибках не сохраняются: они не нужны
для согласованной функции. `text` восстанавливается из `value`.

## JSON v1

```json
{
  "version": 1,
  "entries": [
    { "expression": "2+3", "value": { "re": 5, "im": 0 } },
    { "expression": "i*i", "value": { "re": -1, "im": 0 } }
  ]
}
```

`version` равен `1`, `entries` — массив. У записи строковый `expression`
и конечные компоненты `value.re`, `value.im`; отрицательный ноль
нормализован. При восстановлении вычисление заново не запускается.
Точное расположение файла и интерфейс I/O определяются Plan этапа истории.

## Undo

- Undo удаляет ровно одну последнюю успешную запись и сохраняет обновлённый
  JSON. Это отмена записи в истории, а не обратная арифметическая операция.
- После удаления отображается новая последняя запись; если записей нет,
  показывается пустая история без предыдущего результата.
- Undo на пустой истории — безопасное отсутствие изменений.
- Повторный Undo последовательно удаляет более ранние записи. Redo не входит
  в согласованный scope.
- Проверочный сценарий следующего этапа: успех `2+3`, успех `i*i`, ошибка
  `1/0`, Undo → остаётся только запись `2+3`; после перезапуска она сохранена.

## Загрузка и ошибки сохранения

- Отсутствующий файл означает первоначально пустую историю.
- Повреждённый JSON, неизвестная версия или неправильная структура —
  управляемый отказ загрузки, а не молчаливая замена файла пустой историей.
- Если сохранить добавление или Undo не удалось, изменение истории не
  считается завершённым; прежние записи сохраняются. Расчёт при этом может
  быть математически успешным, но нельзя показывать его как сохранённый.
- Файловые ошибки принадлежат будущему слою истории; они не расширяют
  пять кодов чистого `calculate` из [calculation.md](calculation.md).

Это проектные решения текущего пакета документов. Факт пользовательской
приёмки реализации истории не заявляется.
