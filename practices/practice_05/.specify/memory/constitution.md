# Calculator Constitution

## Core Principles

### I. Спецификация до реализации

Фиксировать поведение, ошибки и проверяемые сценарии до изменения кода.
Текущий запрос разрешает подготовить Spec и Plan первой части.
История и Undo остаются следующим этапом.

### II. Разделение разбора и вычисления

Парсер строит дерево выражения, не выполняя арифметику. Вычислитель работает
с деревом и не разбирает исходную строку. Архитектура согласована пользователем.

### III. Единый числовой тип

В новом вычислительном ядре все значения имеют действительную и мнимую
компоненты. Вещественное число — комплексное с нулевой мнимой частью.
Этот выбор согласован пользователем.

### IV. Проверяемый контракт

Для каждого требования должны быть приёмочные сценарии. План проверок
охватывает грамматику, арифметику, ошибки и существующие 7 регрессионных
тестов. Проверка документов не считается проверкой будущей реализации.

### V. Границы текущей части

Развивать существующий JavaScript-проект. Не добавлять в первую часть
хранилище, UI, сервер, зависимости приложения или операции сверх
согласованных `+ - * /` и скобок. Вычисление не исполняет пользовательский код.

## Development Workflow

Spec → Plan и контракты → последующая декомпозиция Tasks → реализация →
проверки. Смена этапа не делает черновые решения о контракте автоматически
принятыми человеком.

## Governance

Архитектурные принципы II–III взяты из согласования в диалоге.
Остальные пункты описывают рабочие границы этого пакета планирования;
они не являются отдельным заявлением о приёмке студентом.
Изменение публичного поведения отражается в Spec и контрактах.
